# 🎬 Demo Script

> **Purpose**: Maintain a continuously updated, rehearsal-ready demo script.  
> **When to update**: When features are added, removed, or the product direction shifts.  
> **Target duration**: 3–5 minutes (confirm with hackathon rules).

---

## Pre-Demo Checklist

- [ ] App is deployed and accessible via public URL
- [ ] Test the full flow on the demo machine/browser
- [ ] Close unnecessary tabs and notifications
- [ ] Set browser zoom to 100%
- [ ] Clear browser cache / use incognito
- [ ] Have backup screenshots ready in case of live demo failure
- [ ] Silence phone notifications
- [ ] Know your time limit

---

## Demo Structure

### 1. 🎣 Opening Hook (30 seconds)

**Goal**: Grab attention immediately. Start with the problem, not the solution.

> *"Have you ever [experienced the problem]? [Statistic or relatable scenario]. We built [Product Name] to solve this."*

**Rules**:
- No "Hi, we're Team Vector" as the first sentence
- Lead with the pain point
- Make judges feel the problem before showing the solution

**Time**: 0:00 – 0:30

---

### 2. 🖥️ Core Product Demo (2–3 minutes)

**Goal**: Show the product working. Let it speak for itself.

#### Flow Order:

| Step | What to Show | Talking Points | Time |
|---|---|---|---|
| 1 | Landing page / first impression | Design quality, branding | 15s |
| 2 | Primary user action | Core value proposition | 45s |
| 3 | AI-powered feature | How AI adds value (not gimmick) | 45s |
| 4 | Result / output | "Wow" moment | 30s |
| 5 | Secondary feature | Depth & polish | 30s |

**Rules**:
- Never show a feature that isn't working
- Never say "and if we had more time..."
- Show the happy path. Keep it smooth.
- Let the product do the talking

**Time**: 0:30 – 3:00

---

### 3. 🧠 Technical Highlights (45 seconds)

**Goal**: Show judges the technical quality without boring them.

**Key points to mention**:
- Architecture decisions (keep it brief)
- AI integration — how we used AI meaningfully, not just as a wrapper
- Sponsor technology usage and why it made the product better
- Memory layer (Breeth) if applicable — what it remembers and why

**Rules**:
- No code slides unless they illustrate something impressive
- Focus on "why" not "how"
- Keep it accessible to non-technical judges

**Time**: 3:00 – 3:45

---

### 4. 📊 AI Steering Showcase (30 seconds)

**Goal**: Demonstrate thoughtful AI usage throughout development.

> *"We used AI not just in the product, but in building it. Our PROMPTS.md logs every AI interaction, our architecture was AI-reviewed, and our code quality was maintained through AI-assisted reviews."*

**Time**: 3:45 – 4:15

---

### 5. 🎯 Closing Statement (30 seconds)

**Goal**: End strong with a memorable takeaway.

> *"[Product Name] isn't just a hackathon project — it's a [bold claim about the product's potential]. We're Team Vector, and this is [Product Name]."*

**Rules**:
- Restate the problem and solution in one sentence
- End with confidence
- Don't trail off

**Time**: 4:15 – 4:45

---

## 🚫 Screens to Avoid During Demo

| Screen | Why |
|---|---|
| Settings page | Not impressive, wastes time |
| Error states | Good to have, bad to show live |
| Admin panels | Unless core to the product |
| Loading screens | Pre-load everything |
| Blank states | Show the product with data |
| Code editor | Unless you're demoing a dev tool |

---

## 🆘 Contingency Plan

| Scenario | Response |
|---|---|
| Live demo crashes | Switch to pre-recorded video in `assets/demo/` |
| Wi-Fi is down | Have screenshots in `assets/screenshots/` |
| Feature breaks mid-demo | Skip to next feature. Never debug live. |
| Running out of time | Jump to closing statement |
| Judge asks tough question | Be honest. "Great question, we considered that and decided X because Y." |
